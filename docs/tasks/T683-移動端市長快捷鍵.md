# T683 移動端頂欄的 AI 市長
<!-- card: families=無; valve=?noT683 / window.__noT683; owner_ok=; removed_asserts=0 -->

**Claim**　GPT (Codex)，2026-11-21，分支 `gpt/town-mobile-mayor-t683`，基準 `0876ff0`（v11.257）。

**業主原話**　「移動端包含手機端加一個AI 市長按鈕到 加速鍵的 左側，以你覺得合理的間距排列」。

## 交付與範圍

在現有手機頂欄及較寬的觸控平板，把遊戲原有的「AI 市長」放在加速鍵正左方。市長鍵顯示目前開關狀態，也保留城市選單入口。沿用既有城市治理、時間與存檔功能。改動限於頂欄樣式、原按鈕的排列與狀態同步、版本文件和本卡驗證。

## 驗收

- 320、390 像素寬的手機、約 712 寬的截圖版面、手機橫向及較寬觸控平板，市長與速度同排相鄰。兩鍵的觸控區各至少 44 × 44 CSS px，間距 4 至 8 px。正常遊戲及較長數字時，日期、速度和存檔都可讀可點。
- 觸控、鍵盤和「城市 → 市政與營運」皆操作同一個市長。顯示狀態與實際治理一致，點市長不改速度，點速度不改市長。新城、舊檔缺少 AI 欄位、已啟用的存檔分別驗證。
- 一般桌面沿用既有按鈕排列。載入前 `window.__noT683=true` 或 `?noT683=1` 可回到前版排法，T682 回退仍可使用。
- 使用獨立瀏覽器環境與槽 3，取得實際畫面、幾何與操作結果，並驗證完整守衛及正式遊玩頁。渲染、美術與 AI 模擬規則不在本卡施工範圍。

## 驗收紀錄

Chrome 的 56 項幾何、觸控、鍵盤、存讀與回退檢查通過。兩鍵的實際間距在 320 與 390 寬為 4 px，在 712 寬約 7.1 px，在 844 與 1024 寬為 8 px。320 寬顯示長日期和市長通知時仍可點選速度與存檔。進入新城、還原治理中的存檔及讀取缺少市長欄位的舊檔，頂欄皆跟隨城市實際狀態。
